# สำนักเซียน (Prototype)

โปรเจกต์เกมต้นแบบแนวบริหารสำนักและฝึกตน พัฒนาด้วย Godot 4.7 ขณะนี้มีฉากทดลองบริหารสำนักที่เล่นข้ามวันได้ พร้อมระบบข้อมูลตัวละครและระบบต้นแบบสำหรับแผนที่กับการต่อสู้

## วิธีเปิดและทดลอง

1. เปิด Godot 4.7 แล้ว Import โปรเจกต์โดยเลือกไฟล์ `project.godot` ในโฟลเดอร์นี้
2. กด `F6` เพื่อรันฉากที่เปิดอยู่ หรือกด `F5` เพื่อรัน Main Scene
3. จากเมนูหลัก เลือกฉากทดสอบสำนัก แผนที่ หรือการต่อสู้

ฉากทดสอบสำนัก (`scene/test_sect.tscn`): สั่งศิษย์ฝึกหรือออกภารกิจ ใช้ปุ่มข้ามวันเพื่อรับผลลัพธ์ และทดลองทะลวงคอขวดหรือเรียนวิชา

## สถานะระบบ

| ระบบ | สถานะปัจจุบัน |
| --- | --- |
| เมนูหลัก | เปิดฉากทดสอบสำนัก แผนที่ และต่อสู้ได้ |
| บริหารสำนัก | ฉากทดสอบสร้างสำนักและศิษย์ตัวอย่าง สั่งฝึก/ทำภารกิจ และข้ามวันได้ |
| ฝึกตน | มีการคำนวณขั้น ค่าประสบการณ์ที่ต้องใช้ และโอกาสทะลวง |
| AI และเหตุการณ์สำนัก | มีตรรกะพื้นฐานเรื่องความหิว กิจกรรม ความสัมพันธ์ และเหตุการณ์สุ่ม |
| แผนที่ | มี UI เลือกสถานที่ตัวอย่าง การส่งศิษย์ยังไม่ทำงานจริง |
| ต่อสู้ | มีฉากเดโมผลัดกันโจมตี แต่ยังไม่เชื่อมค่าพลังจาก UnitData หรือ TurnManager |
| บันทึก/โหลดเกม | ยังไม่มี |

สถานะข้างต้นอธิบายจากโค้ดปัจจุบัน ฉากเหล่านี้ยังเป็นต้นแบบและอาจมีพฤติกรรมที่ต้องปรับเมื่อเริ่มรวมระบบ

## โครงสร้างโปรเจกต์

- `data/` — Resource และข้อมูลเกม: ตัวละคร, ศิษย์, สำนัก, สิ่งปลูกสร้าง, อุปกรณ์, สกิล, แผนที่ และยูนิตตัวอย่าง
- `scene/` — เมนูหลัก ฉากทดสอบสำนัก ฉากต่อสู้ และฉากแผนที่
- `system/` — ตรรกะร่วม เช่น `sect_manager.gd`, `cultivation_sys.gd`, `turn_manager.gd` และ `battle_unit.gd`
- `project.godot` — การตั้งค่าโปรเจกต์และฉากเริ่มต้น

## งานที่ควรทำต่อ

1. **กำหนดแหล่งข้อมูลกลางให้ชัดเจน** — ปัจจุบันฉากทดสอบสร้างข้อมูลศิษย์และสำนักขึ้นมาเอง และ `SectManager` ถูกสร้างในฉาก ขณะที่ Autoload ใน `project.godot` ชื่อ `TestSect` ควรตัดสินใจว่าจะใช้ผู้จัดการแบบ Autoload หรือสร้างตามฉาก แล้วให้ทุกระบบอ้างข้อมูลชุดเดียวกัน
2. **ทำวงจรวันให้ผลลัพธ์สอดคล้องกัน** — แยกการรับผลกิจกรรม การกินอาหาร และ AI รายวันให้ชัด พร้อมตรวจขอบเขตค่าหิว/EXP และกรณีศิษย์ออกจากสำนัก
3. **เชื่อมฉากต่อสู้กับข้อมูลยูนิต** — ใช้ UnitData และ BattleUnit ควบคุม HP/พลังโจมตีจริง แล้วเชื่อม TurnManager และสัญญาณ UI แทนค่าจำลองที่อยู่ใน battle demo
4. **ทำการเดินทางบนแผนที่ให้ครบวงจร** — เลือกศิษย์ ส่งไปสถานที่ คำนวณวันเดินทาง และรับผลภารกิจกลับเข้าสู่ระบบสำนัก
5. **เพิ่มการบันทึกและโหลด** — เมื่อรูปแบบข้อมูลกลางนิ่งแล้ว จึงกำหนดข้อมูลที่ต้องบันทึกและทดสอบการโหลดกลับ
6. **ตรวจการเริ่มเกมและพฤติกรรมหลัก** — หลังเชื่อมระบบแล้ว ทดสอบการข้ามวัน การทะลวง การต่อสู้ และการเดินทาง รวมถึงตรวจชื่อ Autoload และฉากเริ่มต้น

## ข้อควรทราบ

- `README` นี้เป็นภาพรวมของต้นแบบ ไม่ใช่สเปกสุดท้ายของเกม
- หากเปลี่ยนเวอร์ชัน Godot ให้ตรวจความเข้ากันได้กับฟีเจอร์ที่ระบุใน `project.godot`
- ก่อนเพิ่มระบบใหม่ ควรเชื่อมระบบเดิมและกำหนดแหล่งข้อมูลร่วมให้เรียบร้อย เพื่อไม่ให้ฉากทดสอบแต่ละฉากมีสถานะเกมคนละชุด
